# RepoGeist Frontend Architecture

This document describes every source file in the frontend application, its purpose, and its import/export relationships.

## Root-Level Configuration Files

- **`package.json`** - Project metadata, dependencies (@solidjs/router, @solidjs/start, solid-js, @tanstack/solid-query, openapi-fetch, etc.), and npm scripts (dev, build, start, preview).
- **`vite.config.ts`** - Vite configuration (not shown in raw output, configures build/dev settings).
- **`tsconfig.json`** - TypeScript configuration paths and compiler options.
- **`openapi.json`** - OpenAPI specification used by openapi-typescript to generate `src/types/types.ts`.
- **`.gitignore`** - Standard git ignore rules.

## Entry Points

- **`src/entry-client.tsx`** (4 lines) - Client-side entry. Contains `// @refresh reload` directive and mounts the `StartClient` from `@solidjs/start/client` into the `#app` element. Imports nothing from the app codebase; purely bootstrap logic.

- **`src/entry-server.tsx`** (21 lines) - Server-side entry. Creates a handler with `createHandler` from `@solidjs/start/server` that renders the app with SSR, injecting `assets` and `scripts` into the HTML template. Uses `StartServer` component.

- **`src/global.d.ts`** (1 line) - Single line: `/// <reference types="@solidjs/start" />` — enables SolidStart type declarations for environment variables and SSR contexts.

## Styles

- **`src/app.css`** (26 lines) - Tailwind CSS base import (`@import "tailwindcss"`) and CSS root variables defining the color palette (--ground, --surface, --ink, --signal, etc.) and font families (JetBrains Mono, Public Sans). No imports from other source files.

- **`src/styles/landing.css`** - Landing page specific styles (contains Tailwind directives and component styles for the landing page hero, features, tech grid, etc.).

- **`src/styles/canvas.css`** - Canvas page specific styles (layout, drag/zoom/pan controls, terrain background, card styling, side panel, topbar animations).

## Types

- **`src/types/types.ts`** (586 lines) - Auto-generated by `openapi-typescript` from `openapi.json`. Exports a `paths` interface describing every API endpoint (parameters, request/response schemas), a `webhooks` type, a `components.schemas` object with all DTOs (AnalysisStatusDto, RepoCardDto, RepoDetailDto, etc.), and `$defs`/`operations` type aliases. Imported by `src/lib/api-client.ts` via `import type { paths } from "~/types/types"`.

## Core Application

- **`src/app.tsx`** (21 lines) - Root SolidJS component. Imports `Router` from `@solidjs/router`, `FileRoutes` from `@solidjs/start/router`, `Suspense` from `solid-js`, the `app.css` global styles, and `AppProvider` from `./components/AppProvider`. Renders a `<Router>` wrapping `<AppProvider>` and `<FileRoutes />`, enabling client-side routing with SolidStart.

- **`src/components/AppProvider.tsx`** (17 lines) - Creates a singleton `QueryClient` from `@tanstack/solid-query` outside the component scope. Renders a `<QueryClientProvider>` wrapping `{props.children}` and `<SolidQueryDevtools initialIsOpen={false} />`. Used as the app's root provider to inject query client state and debugging tools into the entire tree.

## API & Data Layer

- **`src/lib/api-client.ts`** (5 lines) - Creates an `openapi-fetch` client instance `api` configured with `baseUrl: "http://localhost:5221"`. Uses the `paths` type from `~/types/types` for typed fetch responses. Imported by `src/lib/analysis.ts`, `src/lib/health.ts`, and `src/lib/repos.ts` via the `~/lib/api-client` alias.

- **`src/lib/keys.ts`** (24 lines) - Centralized query-key factories for TanStack Query. Exports `repoKeys` (all, detail), `healthKeys` (history), and `commitActivityKeys` (activity), plus `analysisKeys` (graph, file). Every query/mutation file imports keys from here rather than inlining arrays, enabling SignalR cache-patching handlers to reference exact keys.

- **`src/lib/index.ts`** (4 lines) - Barrel export: re-exports everything from `./keys`, `./repos`, `./health`, and `./analysis`. Consumers import from `~/lib` to get the full surface area.

- **`src/lib/analysis.ts`** (128 lines) - Analysis-related queries and mutations. Exports `analyzeRepoMutation` (POST /api/repos/{owner}/{name}/analyze, triggers Tier 2 analysis job, invalidates graph query on success) and `dependencyGraphQuery` (GET /api/repos/{owner}/{name}/graph, fetches cached dependency graph, returns null on 404). Internal `fetchDependencyGraph` handles the 404→null logic and `response.status` check to avoid TypeScript errors from missing 404ProducesResponseType. Also exports `fileContentQuery` for single-file content (currently 501 Not Implemented). Imports from `@tanstack/solid-query`, `~/lib/api-client`, and `./keys`.

- **`src/lib/health.ts`** (75 lines) - Health-related queries. Exports `healthHistoryQuery` (GET /api/repos/{owner}/{name}/health, historical checks with `normalizeHealthStatus` mapping) and `commitActivityQuery` (GET /api/repos/{owner}/{name}/commit-activity, weekly commit counts with `staleTime: 5m`). Internal `normalizeHealthStatus` maps the CLR enum wire format (0|1|2) to the union `"Up" | "Down" | "Unknown"`. Imports from `@tanstack/solid-query`, `~/lib/api-client`, `./keys`, and `./repos` (for `HealthStatusValue` type).

- **`src/lib/repos.ts`** (142 lines) - Core repo data layer. Exports the `HealthStatusValue` type (`"Up" | "Down" | "Unknown"`), `normalizeHealthStatus` utility, `repoCardsQuery` (GET /api/repos canvas list), `repoDetailQuery` (GET /api/repos/{owner}/{name} detail panel), `createRepoMutation` (POST /api/repos ingest new repo), and `syncRepoMutation` (POST /api/repos/{owner}/{name}/sync force re-sync). Internal `fetchRepoCards` and `fetchRepoDetail` call the API and coerce `healthStatus` via `normalizeHealthStatus`. Imports from `@tanstack/solid-query`, `~/lib/api-client`, and `./keys`.

## Routes

> **Planned restructure (not yet implemented in the files described below):** `src/routes/canvas/index.tsx` as described here currently owns *both* the persistent pan/zoom shell (`stage`/`world`/`view` signal/wheel handlers/`Topbar`) *and* the leaf content (the repo-cards `<For>`). These are being split so the shell survives navigation to the graph/code views instead of remounting. The shell moves into a new layout route, `src/routes/canvas/(canvas).tsx`, which renders `<Outlet/>` inside `.world`; `src/routes/canvas/index.tsx` shrinks to just the cards `<For>` block as a leaf. New leaf routes `src/routes/canvas/[owner]/[name]/index.tsx`, `graph.tsx`, and `code.tsx` are added for the detail/graph/code views. See TechGuide.md §1.1a for the full mechanism and reasoning. The descriptions below document the current (pre-restructure) file as it exists today.

- **`src/routes/index.tsx`** (716 lines) - Landing page component (`LandingPage` default export). A marketing page with animated terrain cards, feature rows, tech strip, and scroll-triggered reveals. Uses signals (`createSignal`, `createEffect`), Solid primitives (`For`, `Show`, `onMount`, `onCleanup`), and `solid-motionone` (`Motion`, `Presence`, `Float`, `Nudge`) for all animations. Imports `~/styles/landing.css`, `solid-js` signals/types, `solid-motionone`/`solid-icons/fi` for icons. Defines helper components: `createInView`, `Float`, `Nudge`, `MaskWords`, `SectionHead`, `FeatureRow`, `VisualCanvas`, `VisualPanel`, `VisualHealth`, `TechStrip`, `Closing`.

- **`src/routes/[...404].tsx`** (25 lines) - Simple 404 Not Found page. Imports `A` from `@solidjs/router` and `FiGithub`, `FiArrowRight` from `solid-icons/fi`. Renders a centered "Not Found" heading with links back to home and about.

- **`src/routes/canvas/index.tsx`** (305 lines, **to be split** — see restructure note above) - Canvas component (`CanvasHome` default export). The main interactive view where repos are displayed as draggable/zoomable cards on a 2D canvas. Manages state: `repos` signal (canvas-local `Repo` view-model), `view` (zoom/pan), `selected` (side panel open), `tab` (overview/graph/code), `adding` (popover state). Uses `createQuery`/`createMutation` from `@tanstack/solid-query`, fetches data via `repoCardsQuery` and `repoDetailQuery` from `~/lib/repos`. Sub-components composed: `Topbar`, `AddRepoPopover`, `RepoCard`, `SidePanel`. Handles pointer events for drag, zoom (wheel + ctrl), and repo selection. Implements `findOpenSpot` for non-overlapping card layout.
  - **Post-restructure:** the `view` signal, `stage`/`world`/`terrain-veil` markup, wheel/pointer handlers, and `Topbar` move to `src/routes/canvas/(canvas).tsx` (a layout route, mounted once for every route nested under `canvas/`). This file keeps the `repos` signal, `repoCardsQuery`, the `<For>` over `RepoCard`, and `findOpenSpot`, and becomes the leaf rendered into the layout's `<Outlet/>` at `/`. `selected`/`tab` (which repo's panel is open, which tab) likely move to being derived from the URL (`/repo/[owner]/[name]`, `.../graph`, `.../code`) via `useParams()`/`useLocation()` rather than local signals, so that opening a repo is a real navigation and the browser back button closes the panel — exact ownership of `selected`/`tab` state is a detail to settle when this is implemented, not fully specified yet.

- **`src/routes/canvas/(canvas).tsx`** (new, not yet created) - Layout route for everything nested under `canvas/`. Renders the persistent pan/zoom shell exactly once — `stage`/`world`/`terrain-veil` DOM, the `view` signal, wheel/pointer pan handlers, and `Topbar` (with its `AddRepoPopover` child) — and renders `props.children` (the matched leaf route) inside `.world`. Per TechGuide.md §1.1a, wraps that `children` in `solid-motionone`'s `<Presence exitBeforeEnter>`, keyed on a `mode` value (`"cards" | "graph" | "code"`) derived from the current route, so switching leaves is an orchestrated exit-then-enter animation rather than an instant swap. This is the file responsible for the shell never unmounting as the person navigates between `/`, `/repo/[owner]/[name]`, `.../graph`, and `.../code`.

- **`src/routes/canvas/[owner]/[name]/index.tsx`** (new, not yet created) - Leaf route for `/repo/[owner]/[name]`. Content depends on the open decision noted in Guide.md: either this renders nothing itself (the overview stays owned by `SidePanel`, unconditionally overlaid regardless of route, as it is today) or it becomes the thing that tells `(canvas).tsx` "overview is the active mode" for `Presence` purposes. Not yet implemented.

- **`src/routes/canvas/[owner]/[name]/graph.tsx`** (new, not yet created) - Leaf route for `/repo/[owner]/[name]/graph`. Per Design.md §3.3, the intent is for this to replace the canvas full-bleed rather than live in `SidePanel`'s fixed-width tab — if that decision is confirmed, this file owns the dependency-graph SVG rendering (TechGuide.md §1.3, `d3-force`-driven) as `(canvas).tsx`'s `Outlet` content. Not yet implemented; current graph UI lives as a tab inside `SidePanel.tsx`.

- **`src/routes/canvas/[owner]/[name]/code.tsx`** (new, not yet created) - Leaf route for `/repo/[owner]/[name]/code`. Same open decision as `graph.tsx`: full-bleed canvas replacement (file nodes laid out spatially, draggable like repo cards) versus staying inside `SidePanel` as a conventional file-tree-plus-editor layout. Not yet implemented; current code UI is `SidePanel.tsx`'s placeholder "not wired up yet" tab.

- **`src/routes/canvas/components/Topbar.tsx`** (40 lines) - Topbar header. Contains the "Repogeist" wordmark, an "add repo" button (with `FiPlus` icon) that toggles the `AddRepoPopover`, and a "fit all repos" crosshair button. Props: `adding`, `toggleAdd`, `recenter`, `setAddBtnRef`, optional `children`. Imports `solid-js` types and `solid-icons/fi` (`FiCrosshair`, `FiPlus`).

- **`src/routes/canvas/components/AddRepoPopover.tsx`** (124 lines) - Popover dialog for adding a new repository. Controls: URL input, busy state, ingest error display. On submit, parses the URL via `parseRepoUrl` (from `./utils`), validates it, then calls `props.onSubmit(parsed)`. Auto-resets form fields when shown. Mounts a `pointerdown` outside-listener to close on clickaway. Imports `solid-js`, `solid-motionone` (`Motion`, `Presence`), `solid-icons/fi` (`FiX`), and `./utils` (`parseRepoUrl`, `EASE_OUT`, `EASE`, `REDUCED`).

- **`src/routes/canvas/components/RepoCard.tsx`** (96 lines) - Individual repo card rendered inside the canvas terrain. Displays repo name, health dot, description, primary language color badge, GitHub and live-demo links. Uses `Motion.article` for entrance animations (opacity/scale based on `fresh` flag). Click handlers call `openRepo` (opens side panel) or stop propagation on link clicks. Imports `solid-js`, `solid-motionone` (`Motion`), `solid-icons/fi` (`FiExternalLink`, `FiGithub`), and `./utils` (`Repo`, `healthText`, `languageColor`, `REDUCED`, `EASE`, `POP`, `repoKey`).

- **`src/routes/canvas/components/SidePanel.tsx`** (301 lines) - Collapsible side panel that appears when a repo card is clicked. Tabs: **Overview** (health dot, description, languages breakdown (byte-size bars + legend), contributors avatars, GitHub/live-demo links), **Graph** (dependency graph visualization with nodes/edges), **Code** (placeholder "not wired up yet"). Fetches detail data via `repoDetailQuery` from `~/lib/repos` using a `createQuery`/`createMemo` pattern. Imports `solid-js` signals/primitives, `@tanstack/solid-query`, `solid-icons/fi` (`FiExternalLink`, `FiGithub`, `FiX`), and `./utils` (`Repo`, `healthText`, `languageColor`).

- **`src/routes/canvas/components/utils.ts`** (140 lines) - Pure utility functions shared across canvas components. Exports:
  - `Health` type (`"up" | "down" | "unknown"`), lowercase mirror of the API health status.
  - `languageColor` - lookup table (TypeScript, JavaScript, Python, Go, Rust, etc.) with hash fallback for unknown languages.
  - `Repo` interface - canvas view-model with `owner`, `name`, `description`, `primaryLanguage`, `health`, `demo`, `x`, `y`, `fresh`.
  - `repoCardToRepo` - maps `RepoCardDto` (API shape) into the canvas `Repo`.
  - `healthStatusToHealth` - converts API `HealthStatusValue` to canvas `Health`.
  - Constants: `CARD_W` (292), `CARD_H` (148), `EASE`, `EASE_OUT`, `POP` animation curves.
  - `REDUCED` - `prefers-reduced-motion` media query check.
  - `healthText` - display strings per health state.
  - `OWNER_RE`, `NAME_RE` - regex validation for repo URL parsing.
  - `parseRepoUrl` - parses `github.com/owner/repo` URLs into `{ owner, name, url }`.
  - `clamp` and `wrapOffset` math utilities.
  - `repoKey` - generates `"owner/name"` key string.
  Imports `~/lib/repos` for `RepoCard` type and `HealthStatusValue`.

## Data Flow Summary

1. **Landing page** (`routes/index.tsx`) → static marketing page with no API calls.
2. **Canvas** (`routes/canvas/index.tsx`) → fetches `repoCardsQuery` on mount, reconciles server data into local canvas state via `createEffect`.
3. **Adding a repo** → `Topbar` → toggles `AddRepoPopover` → user enters URL → `parseRepoUrl` validates → `createRepoMutation` POSTs to `/api/repos` → on success, invalidates `repoCardsQuery` and reconfigures layout.
4. **Opening side panel** → click a `RepoCard` → `openRepo` sets `selected` signal → `SidePanel` fetches `repoDetailQuery` for that repo's owner/name.
5. **Health status** → all health values flow through `normalizeHealthStatus` in `repos.ts` and `health.ts` to convert CLR int enums to `"Up"\|"Down"\|"Unknown"` unions, then to lowercase `Health` type in `utils.ts` for canvas display.
6. **Analysis** → `analyzeRepoMutation` triggers backend analysis job, invalidates graph cache on success; `dependencyGraphQuery` fetches the computed graph (returns null if not yet analyzed).
7. **(Planned) Navigating between canvas modes** → once the `(canvas).tsx` layout route split lands, moving between `/`, `/repo/[owner]/[name]`, `.../graph`, and `.../code` no longer remounts `stage`/`world`/`view` — only the `<Outlet/>` content swaps, animated via `<Presence exitBeforeEnter>`. Pan/zoom position set before navigating is still there on return. See TechGuide.md §1.1a.
